# v0.6 draft release notes: BarnCRM Core on its own, for any organization

Draft lines for the v0.6 release notes, written for Maria (plan Section 7.5). Feature C-29,
ADR-0059: Core is neutral, and everything about gifts and receipts comes with Giving.

- **New names for the everyday places.** The Nonprofit Hub app is now called **BarnCRM**,
  and Nonprofit Settings is now **BarnCRM Settings**. The Nonprofit Admin, Staff, Read Only
  and Duplicate Review permission sets and the Manage Nonprofit Settings permission are renamed
  the same way. Nothing moved: the same tabs, pages, sections and settings, with new names.
- **Organizations that are not nonprofits can use BarnCRM Core on its own.** Without the
  Giving module, Core now says nothing about gifts, donors or receipts: the Setup Assistant has
  seven steps, the organization step asks only for your legal name and address, and Health
  Check asks no receipt questions.
- **With Giving installed, the steps and settings are where they were.** The Setup Assistant
  still has eight steps in the same order: Giving adds the default fund and appeal step, the
  tax identification number, logo, signature and signer on the organization step, and the
  first gift check. Your receipt settings are in the same Organization section of BarnCRM
  Settings, and Health Check still reports failed receipts and anyone holding Override Receipt
  Lock.
- **Some wording changes even with Giving installed**, because Core's own text is the same for
  every organization:
  - the app, BarnCRM Settings, the Manage BarnCRM Settings permission and the BarnCRM
    permission sets have their new names;
  - the **Generic donor list** import template is now the **Generic contact list**;
  - Health Check, household merge and other Core messages speak of records, contacts and
    totals rather than gifts and donors.
  With Giving installed, the import wizard's gift columns and control total keep their
  wording; the Import Template field Donation Matching is now **Payment Matching**.
- **Fundraising Staff comes with Giving.** The role is listed on the Access page when Giving is
  installed, as before.

## Other products are named only where they are in your org

Owner decision of 2026-10-12 (ADR-NEXT,
`NEXT-core-names-other-products-only-when-detected.md`). Core no longer names NPSP or
Nonprofit Cloud, or speaks of gifts, unless that product or the Giving module is in your
org.

- **"Agentforce Nonprofit" is called "Nonprofit Cloud" again.** The coexistence modes are
  **Standalone**, **NPSP coexistence** and **Nonprofit Cloud coexistence**.
- **You see only the coexistence modes that fit your org.** Standalone is always there. NPSP
  coexistence appears only when NPSP is installed, and Nonprofit Cloud coexistence only when
  BarnCRM finds Nonprofit Cloud objects. The mode you already saved is always shown. The
  Setup Assistant's first step and BarnCRM Settings show the same list.
- **A different recommendation for Person Accounts.** BarnCRM recommends Nonprofit Cloud
  coexistence when it finds Nonprofit Cloud, otherwise NPSP coexistence when it finds NPSP,
  otherwise Standalone. An org with Person Accounts and no Nonprofit Cloud is now
  recommended Standalone; BarnCRM still proposes one membership record per person, because
  Person Accounts need it, and never overwrites a membership choice you already made.
- **Plainer wording in step one.** It now reads "If your org uses Person Accounts, household
  membership uses the junction model so that what you already have keeps working. Confirm
  that here, or choose a different fit." A fresh org reads "This looks like a fresh org,
  with no other household model and no Person Accounts. BarnCRM can run on its own."
- **Step six lists the modules that fit.** Without Giving you see Core and Volunteers, plus
  any other module you have installed; with Giving you see all six. Each **Learn more** link
  now opens that module's description on GitHub.
- **No gift columns in the import wizard without Giving.** A column for an amount or a date
  that only a module could load is suggested as **Do not load**. Nothing in your file is
  lost: the staged row still keeps the whole line.
- **The Nonprofit Cloud and NPSP person templates come with Giving.** "Nonprofit Cloud:
  person accounts" and the NPSP contacts template are created only in an org that has
  Giving, alongside Giving's other migration templates.
- **The install warning names BarnCRM.** If the BarnCRM Admin role was not ready at
  install, the Error Log entry now says to open BarnCRM Settings, then Access, and give
  the installer the BarnCRM Admin role.
- **Two admin-guide pages have new addresses**: the BarnCRM app page is `barncrm-app.md`
  and the BarnCRM Settings page is `barncrm-settings.md`.
