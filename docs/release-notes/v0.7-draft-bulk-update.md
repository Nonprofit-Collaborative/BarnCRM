# v0.7 draft release notes: Bulk update

Draft lines for the v0.7 release notes, written for Maria (plan Section 7.5). Feature C-35
(ADR-NEXT, `NEXT-bulk-update-runs-as-the-user-from-a-find-query.md`; canonical model Section
29E, R-BU1 to R-BU6; admin guide `bulk-update.md`).

- **Change many records at once, and take it back.** Run a query in **Find**, press **Bulk
  update**, and change up to five fields on every record it returns: set a value, clear it, or
  copy another field of the same record. See [Bulk update](../admin-guide/bulk-update.md).
- **See it before it happens.** Bulk update counts the matching records and shows the first five
  before and after. You type that number to confirm; if more records match by the time you
  confirm, nothing changes.
- **Your own access, and your organization's rules.** A bulk update changes only records and
  fields you may edit, and validation rules, duplicate rules and automation run as on any save.
  A record that is refused is listed with the reason; the rest still save.
- **Progress and undo.** The update runs in the background with a progress bar. For as long as
  an import can be undone (30 days unless you change it), the **Bulk Update** tab can undo it:
  each value goes back, except one somebody has changed since.
- **What BarnCRM keeps itself stays safe.** Rollup totals, household greetings, member counts,
  formula and system fields, and BarnCRM's own records cannot be bulk updated.
- **Who can use it.** The BarnCRM Admin role, or anyone given the new **BarnCRM Bulk Update**
  permission set together with **BarnCRM Find and Export**. A new setting in BarnCRM Settings,
  Import, **Bulk update run limit** (48,000 unless you lower it), caps one bulk update.
