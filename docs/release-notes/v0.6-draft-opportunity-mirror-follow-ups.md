# v0.6 draft release notes: Opportunity mirror follow-ups

Draft lines for the v0.6 release notes, written for Maria (plan Section 7.5). Not a feature;
review follow-up 5 (plan Section 11.3) to the Opportunity mirror (X-01) and receipts (C-29).

- **`Master` in the record type list is named.** Listing `Master` in **Opportunity mirror
  record types** matched no Opportunity, without a word, because an Opportunity without a
  record type stores none. A run now leaves `Master` out and writes one Warning to the Error
  Log saying so. To include Opportunities without a record type, leave the list empty.
- **Overlapping runs are recognized more precisely.** When two runs make a gift from the same
  Opportunity at once, the second is counted as unchanged only when Salesforce names the gift's
  Opportunity ID field itself, never a field with a similar name.

For contributors: `OpportunityMirrorService.unavailableForTest` makes a test org look like one
without Opportunity, and `OpportunityMirrorUnavailableTest` runs that path. The Connect tests
that stop early where Opportunity is absent now assert what happened first. The receipt
failure count test now checks that the capped count reads no more rows than the cap allows.
