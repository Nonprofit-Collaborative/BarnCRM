# v0.6 draft release notes: Import first names

Draft lines for the v0.6 release notes, written for Maria (plan Section 7.5). A fix to import
matching (ADR-0067, canonical model R-IB12).

- **An import no longer renames somebody.** Before, with only John Smith at an address, a
  "Jane Smith" row at that address was matched to John and his first name was changed to
  Jane. Now a row with a different first name is a different person: Jane is created and
  John is left as he was. This applies under **Email exact** (a shared email) and **Name plus
  postal code**, against people you already have and people created earlier in the same
  file.
- **First names are compared ignoring capitals and extra spaces, and nothing else.** "JANE"
  and " Jane " are Jane. An accent, an initial ("J." for John) or a short form ("Bob" for
  Robert) is a different name, so the dry run counts that row as "would create". Check that
  count before you commit, and merge any pairs afterwards from the duplicate scan.
- **A row with no first name still matches** on the email, or surname and postal code, and
  leaves the first name you have as it is.
