# v0.7 draft release notes: Import matching and values for every row

Draft lines for the v0.7 release notes, written for Maria (plan Section 7.5). Feature C-32
(ADR-NEXT, `NEXT-import-matching-per-entity-and-per-file-values.md`; canonical model R-IT2,
R-IT8, R-IT9, R-IB14).

- **Organizations have a matching rule of their own.** Match them by name, as before, or by an
  ID your other system gave them. Only organizations are searched.
- **Match by the ID field you choose.** Under **External ID**, pick the field from the fields
  your org marks External ID or Unique, for people and for organizations. Before, the importer
  used whichever external ID field it found first.
- **A row that matches more than one record is rejected by default.** Before, it was loaded
  into the oldest of them. Now you choose: reject the row (the default), or use the most
  recently changed record. Either way every such row has **Several Matches** ticked, so you can
  find it. A row with no first name, at the email or address of a couple, is the usual case.
- **Values for every row.** Give a file a value its rows share, such as a city missing from
  every row. A row's own value still wins, and the next file starts without it.
